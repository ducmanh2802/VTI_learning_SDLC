## Conventions (apply everywhere)

**Document basics**

- OpenAPI `3.1.0`; `info.version: 0.1.0`.
- `servers`: `[{url: /api/v1}]` for public, `[{url: /internal/v1}]` for internal.
- Paths are relative to the server URL, so write `/auth/login`, not `/api/v1/auth/login`.

**Operations**

- Every operation has a unique camelCase `operationId`, a `summary`, `tags`, `security`, and responses.
- Tags are the module names: `identity`, `consent`, `market`, `ai`, `watchlist`, `alerting`, `notification`, `paper`, `support`, `content`, `admin`, `telemetry`.

**Security schemes**

- `bearerAuth`: HTTP bearer, `bearerFormat: JWT`.
- `refreshCookie`: apiKey in cookie `refresh_token`.
- Internal API: `serviceToken`, apiKey in header `X-Service-Token`.
- Public endpoints with Auth "—" in SDD 3.6.1 use `security: []`.
- Admin endpoints use `bearerAuth` and say in their description that the caller must have role ADMIN.

**Errors**

- Every 4xx/5xx response uses media type `application/problem+json` with schema `Problem`:
  - `type` (uri), `title`, `status`, `detail`, `code`, `correlationId` (uuid).
  - `errors`: optional array of `{field, message}`.
- `code` is an enum containing exactly the codes in the SDD 3.6.1 error table, plus `INVITE_INVALID`.
- Define reusable responses `BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `Unprocessable`, `TooManyRequests`, `ServiceUnavailable` and reference them.

**Data types**

| Kind | Schema |
|---|---|
| Identifiers | `type: string, format: uuid` |
| Timestamps | `format: date-time`; trading dates `format: date` |
| Money (VND) | `type: integer, format: int64` |
| Prices / index points | `type: number, multipleOf: 0.01` |
| Percent | `type: number` |
| Symbol codes | `type: string, pattern: '^[A-Z0-9]{2,20}$'` |
| JSON property names | camelCase |

- Every market payload includes a `provenance` object `{source, asOf, kind: [DELAYED, CALCULATED, CLOSE], stale: boolean}` (FR-029, FR-030).
- AI payloads, `AiSummary` and `AiChatResult`, contain:
  - `interactionId`, `status: [PUBLISHED, FALLBACK, REFUSED]`, `text` (nullable when FALLBACK);
  - `citations: [{id, label, value, unit, source, asOf}]`, `facts` (same item shape);
  - `labels: {aiGenerated: true, notAdvice: true}`.

**Lists and idempotency**

- Lists use cursor pagination: query `limit` (1–100, default 20) and `cursor`; response `{items: [...], nextCursor: string|null}`.
- `POST /paper/orders` requires header `Idempotency-Key` (uuid).

## Steps

### 1. `public.yaml`

Include **every** row of the SDD 3.6.1 table. This includes the v0.2 rows:

- `POST /auth/register` with `inviteCode`;
- `POST /events`;
- `GET/POST /admin/invites` and `POST /admin/invites/{id}/revoke`.

Expand the combined rows into separate operations (for example `GET /watchlists` and `POST /watchlists`).

Request and response bodies:

- `register`: `{email, password, inviteCode?, acceptedTerms: [version], consents: {P2: bool, P3: bool, P4: bool}}`.
- `login`: `{email, password, totp?, client: [WEB, MOBILE]}` → `{accessToken, expiresIn, refreshToken?}`. `refreshToken` is returned only for MOBILE; WEB gets the `refresh_token` cookie.
- `refresh`: accepts the cookie (WEB) or the body `{refreshToken}` (MOBILE).
- `GET /symbols/{code}/bars`: query `interval` with enum `D`, `W`, `M`; plus `from` and `to`.
- `GET /market/treemap`: query `weight` with enum `VALUE`, `COUNT`, `ADVANCERS`; query `dir` with enum `ALL`, `UP`, `DOWN`.
- `POST /paper/orders`: body `{symbol, side: [BUY, SELL], orderType: [LO, MP], quantity (integer ≥ 100, multipleOf 100), limitPrice?}`. Responses: 201 `PaperOrder`; 422 `Problem` with a `RISK_*` code; 503 `DATA_STALE`.
- `POST /events`: `{events: [ProductEvent] (maxItems 50)}` → 202.
  - `ProductEvent` = `{event, occurredAt, platform: [web, android, pwa], sessionId?, properties: object}`.
  - `event` is an enum with the event names in PRD 6.2.
- Admin `POST /admin/invites`: `{label?, maxUses (1–1000), expiresAt}` → 201 `{id, code, label, maxUses, expiresAt}`. Document that `code` is returned only in this response.

### 2. `internal.yaml`

Include every row of SDD 3.6.2. `POST /ai/chat` takes `{userRef, question (maxLength 500), contextSymbol?}` and returns `AiChatResult` plus `refunded: boolean`. Health endpoints use `security: []`.

### 3. Reuse

Put shared schemas in `components/schemas`. The internal and public specs may duplicate shared schemas; do not `$ref` across files.

Include at least one `example` each for: `Quote`, `AiSummary` (PUBLISHED and FALLBACK), the `Problem` for `RISK_LOT_SIZE`, and `PaperOrder`.

### 5. Event contracts

- `contracts/events/redis-keys.md`: the SDD 3.5.3 table, verbatim, plus a writer/reader column and the TTL of each key.
- `contracts/events/s-quotes.schema.json`: JSON Schema draft 2020-12 for one `s:quotes` stream entry: `cycle_id` (string), `ts` (epoch ms integer), `session` (enum of the SRS session states), `symbols` (comma-separated string of symbol codes; give a pattern).
- `contracts/events/examples/s-quotes.example.json`: one valid entry.

- Triggers: `pull_request`; `push` on `main`, `integration/**` and `wp-*`. Permissions: `contents: read`.
- Job `lint-contracts` on Node 20 runs acceptance commands 1–3.

### 7. READMEs and report

- `contracts/openapi/README.md` and `contracts/events/README.md`: how to lint, and the rule "contracts change only in a WP that says so".
- Report `docs/workpackages/reports/WP-02.md`. It must include a table with one row per path from SDD 3.6.1/3.6.2: **SDD row → method + path → operationId**.
