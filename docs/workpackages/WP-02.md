## Goal

Write the machine-readable contracts that every later WP codes against:

- the Core public API (served under `/api/v1`);
- the Analytics internal API (`/internal/v1`);
- the Redis key contract and the `s:quotes` stream schema.

Bundled single-file copies are committed in `contracts/openapi/dist/` for code generation (WP-03, WP-07).

## Layout (create exactly this structure)

```text
contracts/openapi/
  redocly.yaml                      lint config + the two API definitions
  public.yaml                       root: openapi, info, servers, tags, securitySchemes, paths (each value is a $ref)
  public/paths/<name>.yaml          one Path Item per file, e.g. auth_login.yaml, symbols_{code}_quote.yaml
  public/schemas/<Name>.yaml        one schema per file, e.g. Problem.yaml, Quote.yaml, PaperOrder.yaml
  public/responses/<Name>.yaml      BadRequest.yaml, Unauthorized.yaml, ... (each references ../schemas/Problem.yaml)
  public/parameters/<Name>.yaml     SymbolCode.yaml, Cursor.yaml, Limit.yaml, IdempotencyKey.yaml
  internal.yaml                     root for the internal API
  internal/paths/*.yaml, internal/schemas/*.yaml, internal/responses/*.yaml
  dist/public.yaml                  generated by `redocly bundle` (commit it; never edit it by hand)
  dist/internal.yaml                generated by `redocly bundle`
contracts/events/
  redis-keys.md, s-quotes.schema.json, examples/s-quotes.example.json, README.md
```

**Reference rules:**

- Paths in a root file look like `/auth/login: { $ref: './public/paths/auth_login.yaml' }`.
- Inside a path file, refer to `../schemas/X.yaml`, `../responses/Y.yaml` or `../parameters/Z.yaml`.
- The public and internal specs do not reference each other's files. Duplicate a small shared schema if both need it.

**File naming:** path files use the path with `/` → `_` and the braces kept, e.g. `/symbols/{code}/quote` → `symbols_{code}_quote.yaml`.

## Conventions (apply everywhere)

**Document basics**

- OpenAPI `3.1.0`; `info.version: 0.1.0`.
- `servers`: `[{url: /api/v1}]` for public, `[{url: /internal/v1}]` for internal.
- Paths are relative to the server URL.

**Operations**

- Every operation has a unique camelCase `operationId`, a `summary`, `tags`, `security` and responses.
- Tags are: `identity`, `consent`, `market`, `ai`, `watchlist`, `alerting`, `notification`, `paper`, `support`, `content`, `admin`, `telemetry`.

**Security schemes**

- `bearerAuth`: HTTP bearer, `bearerFormat: JWT`.
- `refreshCookie`: apiKey in cookie `refresh_token`.
- Internal API: `serviceToken`, apiKey in header `X-Service-Token`.
- Endpoints with Auth "—" in SDD 3.6.1 use `security: []`.
- Admin endpoints say in their description that the caller must have role ADMIN.

**Errors**

- Every 4xx/5xx uses `application/problem+json` with schema `Problem`:
  - `type` (uri), `title`, `status`, `detail`, `code`, `correlationId` (uuid);
  - `errors`: optional array of `{field, message}`.
- `code` is an enum of exactly the SDD 3.6.1 error-table codes, plus `INVITE_INVALID`.
- Reusable responses: `BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `Unprocessable`, `TooManyRequests`, `ServiceUnavailable`.

**Data types**

| Kind | Schema |
|---|---|
| Identifiers | uuid |
| Timestamps | `date-time`; trading dates `date` |
| Money (VND) | `integer`, `int64` |
| Prices / index points | `number`, `multipleOf: 0.01` |
| Percent | `number` |
| Symbol codes | `string`, pattern `^[A-Z0-9]{2,20}$` |
| JSON property names | camelCase |

- Every market payload has `provenance: {source, asOf, kind: [DELAYED, CALCULATED, CLOSE], stale: boolean}`.
- AI payloads (`AiSummary`, `AiChatResult`) have:
  - `interactionId`, `status: [PUBLISHED, FALLBACK, REFUSED]`, `text` (nullable);
  - `citations: [{id, label, value, unit, source, asOf}]`, `facts` (same item shape);
  - `labels: {aiGenerated: true, notAdvice: true}`.
- The overview schema (`MarketOverview`) has `unavailable: [string]`. It lists sections missing because of the data-source tier, for example `volume_spike` and `treemap_value`.

**Lists and idempotency**

- Lists use cursor pagination: `limit` (1–100, default 20), `cursor` → `{items, nextCursor}`.
- `POST /paper/orders` requires header `Idempotency-Key` (uuid).

## Steps

### Public API (every row of SDD 3.6.1, including the v0.2 rows)

Expand the combined rows into separate operations. Required bodies:

- `register`: `{email, password, inviteCode?, acceptedTerms: [version], consents: {P2: bool, P3: bool, P4: bool}}`.
- `login`: `{email, password, totp?, client: [WEB, MOBILE]}` → `{accessToken, expiresIn, refreshToken?}`. `refreshToken` is MOBILE only; WEB gets the `refresh_token` cookie. `refresh` accepts the cookie or the body `{refreshToken}`.
- `bars`: query `interval` with enum `D`, `W`, `M`; plus `from` and `to`.
- `treemap`: query `weight` with enum `VALUE`, `COUNT`, `ADVANCERS`; query `dir` with enum `ALL`, `UP`, `DOWN`.
- `POST /paper/orders`: `{symbol, side: [BUY, SELL], orderType: [LO, MP], quantity (integer, minimum 100, multipleOf 100), limitPrice?}` → 201 `PaperOrder`, 422 `Problem` with `RISK_*`, 503 `DATA_STALE`.
- `POST /events`: `{events: [ProductEvent] (maxItems 50)}` → 202.
  - `ProductEvent` = `{event (enum of the PRD 6.2 event names), occurredAt, platform: [web, android, pwa], sessionId?, properties}`.
- `POST /admin/invites`: `{label?, maxUses (1–1000), expiresAt}` → 201 `{id, code, label, maxUses, expiresAt}`. The code is returned only here.
- Add `GET /health` (`security: []`, tag `support`) → `{status: [UP, DOWN], components: {db, redis}}`.

Include at least one `example` each for: `Quote`, `AiSummary` (PUBLISHED and FALLBACK), the `RISK_LOT_SIZE` problem, and `PaperOrder`.

### Internal API

- Every row of SDD 3.6.2.
- `POST /ai/chat` takes `{userRef, question (maxLength 500), contextSymbol?}` and returns `AiChatResult` plus `refunded`.
- Health endpoints use `security: []`.

```yaml
  operation-operationId-unique: error
  operation-summary: error
  operation-4xx-response: error
  security-defined: error
  no-unused-components: warn
  info-license: off
```

### Work loop (important)

1. Write the root file with **only** the security schemes and the first 5 paths, plus their path, schema and response files.
2. Run lint (acceptance #1) and fix everything.
3. Add the next group of ~10 paths, then lint again. Repeat until every SDD row is covered.

### Bundle

- `npx --yes @redocly/cli@1 bundle public --config contracts/openapi/redocly.yaml -o contracts/openapi/dist/public.yaml`
- The same command with `internal`.
- Commit both outputs.

### Events

- `redis-keys.md`: the SDD 3.5.3 table, verbatim, plus writer/reader and TTL columns.
- `s-quotes.schema.json`: JSON Schema 2020-12 with `cycle_id`, `ts` (epoch ms integer), `session` (enum of the SRS session states), `symbols` (comma-separated codes, with a pattern).
- One valid example in `examples/s-quotes.example.json`.

### CI: `.github/workflows/contracts.yml`

- Triggers: `pull_request`; `push` on `main`, `integration/**`, `wp-*`. Permissions: `contents: read`. Node 20.
- Steps:
  1. Lint.
  2. Bundle into a temporary directory, then `diff` against `dist/`, so a stale bundle fails CI.
  3. Validate the events schema with ajv.

### Report

The report includes a table with one row per SDD 3.6.1/3.6.2 row: **SDD row → method + path → operationId → file**.
