## Deviations from the brief

- Added `contracts/openapi/.gitignore` with `!dist/` and `!dist/*.yaml`. The root `.gitignore` ignores every `dist/`, but the brief requires committing the bundles; this re-includes only the two generated files.
- Added a ninth reusable response, `Locked.yaml` (423), because `ACCOUNT_LOCKED` is defined as HTTP 423 in SDD 3.6.1.
- Added shared parameters beyond the four named in the brief (`Id`, `SymbolPath`, `FlagKey`, `CorrelationId`, `Purpose`) to avoid duplicated inline parameter definitions. `CorrelationId` is required on internal operations except the two health probes.
- Facts and citations type `value` as a decimal string (as in the SDD 3.6.2 example) so money and ratios keep exact precision; the brief only names the fields, not their JSON type.
- On Windows I used PowerShell for the temp directory and exit-code handling; no POSIX-only command was needed.

## Questions / open issues

- SDD 3.6.1 combines `GET / POST` with multiple admin paths. I assumed `POST` applies to the action sub-paths (`/lock`, `/unlock`, `/revoke`, `/verdict`) and not to creating users or creating AI reviews; there is no FR for an admin-created user or review. If a `POST /admin/users` (create user) is intended, the contract needs that operation added.
- SDD 3.6.2 lists `GET / POST /ai/reviews`; I mapped `POST` to `/ai/reviews/{id}/verdict`, which is the only write action described in the table.
- `ProductEvent.platform` is `web | android | pwa` per the brief. The database also allows `server` for server-side events; those are emitted internally and are not accepted from clients in this contract.
