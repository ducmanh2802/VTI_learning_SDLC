# WP-01: Baseline migration, migrator service, service DB roles

| Field | Value |
|---|---|
| Size | S |
| Audit level | Standard (A1–A10) |

## Goal

The database schema becomes reproducible from migrations:

- `db/migrations/V1__baseline.sql` is the baseline.
- A Flyway `migrator` service applies it.
- Two least-privilege login roles exist, one per service:
  - `core_svc` is a member of `core_rw`.
  - `analytics_svc` is a member of `analytics_rw`.

## In scope

- `db/migrations/V1__baseline.sql` (new), `db/migrations/README.md` (update)
- `infra/postgres/initdb/10-service-roles.sh` (new)
- `infra/docker-compose.yml` (add `migrator`, mount the initdb folder), `infra/.env.example`, `infra/README.md`
- `.github/workflows/ci.yml` (add a migration job)
- `docs/workpackages/reports/WP-01.md`

## Out of scope

- Any change to `docs/design/schema.sql`.
- Application code.
- Production compose (WP-22).

## Steps

### 1. Baseline migration

Copy `docs/design/schema.sql` to `db/migrations/V1__baseline.sql` **byte for byte**. Do not edit the content. Future schema changes go into `V2__*.sql` and later files.

### 2. Service login roles: `infra/postgres/initdb/10-service-roles.sh`

The script runs once, when the Postgres data volume is first created. Mount the folder at `/docker-entrypoint-initdb.d` (read-only). The file must use LF line endings.

It creates:

- the group roles (NOLOGIN);
- the login roles, with passwords read from the environment variables `CORE_DB_PASSWORD` and `ANALYTICS_DB_PASSWORD`.

Use this exact approach. psql variables are not expanded inside `DO $$` blocks, so the script uses `format()` + `\gexec`:

```sh
#!/bin/sh
set -eu
: "${CORE_DB_PASSWORD:?CORE_DB_PASSWORD is required}"
: "${ANALYTICS_DB_PASSWORD:?ANALYTICS_DB_PASSWORD is required}"
psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" --dbname "$POSTGRES_DB" \
     -v core_pw="$CORE_DB_PASSWORD" -v analytics_pw="$ANALYTICS_DB_PASSWORD" <<'SQL'
SELECT 'CREATE ROLE core_rw NOLOGIN' WHERE NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'core_rw')\gexec
SELECT 'CREATE ROLE analytics_rw NOLOGIN' WHERE NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'analytics_rw')\gexec
SELECT format('CREATE ROLE core_svc LOGIN PASSWORD %L IN ROLE core_rw', :'core_pw')
 WHERE NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'core_svc')\gexec
SELECT format('CREATE ROLE analytics_svc LOGIN PASSWORD %L IN ROLE analytics_rw', :'analytics_pw')
 WHERE NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'analytics_svc')\gexec
ALTER ROLE core_svc SET search_path = core, paper, strategy, market;
ALTER ROLE analytics_svc SET search_path = market, ai, research, strategy;
SQL
```

Pass `CORE_DB_PASSWORD` and `ANALYTICS_DB_PASSWORD` to the `postgres` service environment using `${VAR:?}`.

### 3. `.env.example`

Add these lines, each with a one-line comment:

```dotenv
CORE_DB_PASSWORD=change-me-core
ANALYTICS_DB_PASSWORD=change-me-analytics
```

### 4. `migrator` service in `infra/docker-compose.yml`

- Image `flyway/flyway`, pinned to a specific existing **10.x or 11.x** tag (not `latest`). Verify that the tag exists with `docker pull` before you commit. Flyway Community is free (SC-005).
- `profiles: ["tools"]`, so `up` does not start it; `docker compose run --rm migrator` does.
- `depends_on: postgres: condition: service_healthy`.
- `command: ["migrate"]`.
- Environment:
  - `FLYWAY_URL=jdbc:postgresql://postgres:5432/${POSTGRES_DB}`
  - `FLYWAY_USER=${POSTGRES_USER}`, `FLYWAY_PASSWORD=${POSTGRES_PASSWORD}`
  - `FLYWAY_LOCATIONS=filesystem:/flyway/sql`
  - `FLYWAY_CONNECT_RETRIES=10`
  - `FLYWAY_VALIDATE_MIGRATION_NAMING=true`
- Volume `../db/migrations:/flyway/sql:ro`.
- Network `internal`.

### 5. CI: job `db-migrate` in `.github/workflows/ci.yml`

Steps:

1. Copy env.
2. `up -d --wait postgres`.
3. `run --rm migrator`.
4. Run acceptance checks 4–8 below.
5. `down -v` (with `if: always()`).

Keep the existing jobs unchanged.

### 6. Docs and report

- `db/migrations/README.md`: naming rule `V<n>__<snake_case>.sql`; never edit an applied migration; how to run the migrator.
- `infra/README.md`: describe the new env vars and how to run the migrator.
- Write the report `docs/workpackages/reports/WP-01.md`.

### 7. Follow-ups from the WP-00 audit (in scope)

- **F1:** in the `redis` service command, start the server with `exec redis-server ...`. Then redis-server runs as PID 1 and receives SIGTERM, so it shuts down cleanly and flushes the AOF.
- **F2:** in the `secret-scan` job, run the gitleaks container with `--user "$(id -u):$(id -g)"`, so git inside the container does not fail with "dubious ownership".
- **F3:** add `push` triggers for `integration/**` and `wp-*` branches next to `main`, so CI runs on pushed work-package branches.

## Acceptance
