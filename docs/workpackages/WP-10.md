## Goal

The Analytics scheduler process keeps market data fresh and correct:

| Data | Destination | When |
|---|---|---|
| Symbol master | `market.symbols` | daily |
| Index membership | `market.index_memberships` | daily |
| Live quotes | Redis `q:*`, `ob:*` | every ≤ 60 s during sessions |
| Index levels | Redis `idx:*` | every ≤ 60 s during sessions |
| Session state | Redis `mkt:session` | every 15 s |
| End-of-day bars | `market.daily_bars`, including index bars | after the close |
| History | `market.daily_bars` | backfill when a symbol appears |

Every run is recorded. Bad records are quarantined. The `s:quotes` stream announces each completed quote cycle, so Core (alerts, paper trading) can react.

| DERIV | PRE_OPEN 08:30–08:45; ATO 08:45–09:00; CONTINUOUS 09:00–11:30; LUNCH_BREAK 11:30–13:00; CONTINUOUS 13:00–14:30; ATC 14:30–14:45; POST_CLOSE 14:45–15:00 |

Outside every window the state is `CLOSED`.

**`holidays-vn.yaml`:** a list of non-trading weekdays. Seed it with `2027-01-01`. Comment: "Admin must add each year's official schedule".

### Calendar and session (ALG-01)

- `trading_calendar.is_trading_day(d)`: weekday and not in `holidays-vn.yaml`.
- `market.trading_calendar` is upserted each morning for today and the next 10 calendar days.
- `session_state(exchange, now)` is a pure function of the config.
- A job every 15 s writes the Redis hash `mkt:session` with fields `HOSE`, `HNX`, `UPCOM`, `DERIV` and `updated_at` (epoch ms), following `contracts/events/redis-keys.md`.

### Jobs

The scheduler runs them (APScheduler, timezone Asia/Ho_Chi_Minh). Each job holds a Redis lock `lock:job:{name}` (TTL = job timeout), so instances never overlap. Each run inserts and updates `market.ingestion_runs`.

| Job | Schedule | Work |
|---|---|---|
| `symbols_sync` | 08:00 on trading days, and at startup if the table is empty | `list_symbols()` (equities). Exchange comes from a `get_quotes` pass, since the board carries `exchange`. Upsert `market.symbols` with `kind=STOCK`, `name_search` = lowercase, no diacritics, `đ→d`. Upsert indices `VNINDEX`, `VN30`, `HNXINDEX`, `UPCOMINDEX` (`kind=INDEX`, exchange HOSE/HOSE/HNX/UPCOM). Codes not seen for 3 consecutive days → `is_active=false`. `get_group_members("VN30")` and `"VN100"` upsert `market.index_memberships` with today as `effective_date` |
| `quotes_cycle` | every 60 s while any HOSE/HNX/UPCOM session is ATO, CONTINUOUS or ATC | Fetch all active stocks in batches through the failover provider. Run **quality checks** (below). Write the Redis hash `q:{SYMBOL}` with fields per the contract, `ts` = fetch time, `src` = provenance. Write `ob:{SYMBOL}` (3 levels, TTL 60 s). Then `XADD s:quotes MAXLEN ~ 10000` with `{cycle_id, ts, session, symbols}` (validate against `contracts/events/s-quotes.schema.json`). Then call the hook. Skip the cycle if the previous one is still running. If a cycle takes > 55 s, log WARN |
| `index_cycle` | same schedule as `quotes_cycle` | For the 4 indices: Guest tier has no index quote, so use today's daily bar via `get_index_bars(code, today, today)` and write `idx:{CODE}` |
| `eod_bars` | 15:30 on trading days | Upsert `market.daily_bars` for every active stock and the 4 indices: today's bar, `source` = provenance. Values: equities × 1000 already handled by WP-08; `ref_price`, `ceiling_price`, `floor_price` from the last quote cycle when available |
| `backfill` | on demand, and daily at 16:30 | For symbols with no bars, fetch the allowed history (Guest: 365 days, clamped by WP-08). Budget: ≤ 1 request/s total. Resumable; progress is logged |

### Quality checks (FR-031)

A bad record is **not** written. It goes to `market.quarantine` with a reason.

**Quotes:**

- `floor ≤ price ≤ ceiling` when all three exist;
- `low ≤ high`;
- `price > 0`;
- bid/ask volumes ≥ 0.

**Bars:**

- `low ≤ open, close ≤ high`;
- `volume ≥ 0`;
- `trade_date` is a trading day.

**Run status:**

- More than 5% of records bad → status `DEGRADED`; keep the previous Redis values; do not `XADD`.
- 3 consecutive `FAILED` runs of a job → log an ERROR with `alert=true`. The admin notification hook comes in WP-13 and WP-18.

### Fail-closed contract for consumers (FR-030)

- Every `q:*` and `idx:*` entry carries `ts`.
- Consumers treat data as stale when `now − ts > 120 s` during a session.
- This WP never writes placeholder or zero values for missing data.

### Process

- `python -m analytics.ingestion.scheduler` from WP-07 now registers these jobs. It runs as a **single instance** (compose service `analytics-scheduler`).
- Settings:
  - `INGESTION_ENABLED` (default true in compose, false in tests)
  - `QUOTE_BATCH_SIZE=50`
  - `QUOTE_CYCLE_SECONDS=60`
