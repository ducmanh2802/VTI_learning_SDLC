## Goal

- Users create price / % change / volume alerts.
- The evaluator fires them **once per session**, when a condition goes from false to true on fresh data.
- Notifications go to the inbox and, with consent P2, to email and push, through the transactional outbox with retries.

## Design

### Alert rules (FR-090)

**`POST /alerts {symbol, conditionType, threshold, channels, expiresAt?}`:**

- `conditionType` ∈ `PRICE_GTE`, `PRICE_LTE`, `PCT_CHANGE_GTE`, `PCT_CHANGE_LTE`, `VOLUME_GTE`.
- Threshold limits: price > 0; pct ∈ [−100, 100]; volume > 0.
- The symbol must exist.
- Max 20 non-deleted ACTIVE/COOLDOWN/PAUSED alerts per user (`app.limits.active-alerts=20`), else 409 `LIMIT_EXCEEDED`.
- `channels` ⊆ {IN_APP, EMAIL, PUSH}, non-empty. If EMAIL or PUSH is requested and `ConsentQuery.isGranted(user, "P2")` is false → 400 `VALIDATION_ERROR`, detail "Cần đồng ý nhận thông báo (P2) để dùng email/push".
- On create, initialize the Redis state `alert:st:{id}` from the current quote (UC-009 3a).

**Other endpoints:**

- `PATCH /alerts/{id}`: pause, resume, threshold, channels, expiry.
- `DELETE /alerts/{id}`: soft delete (status DELETED).
- `GET /alerts`: the caller's alerts.
- `GET /alerts/events?cursor=`: last 90 days.

### Evaluator (ALG-09)

- `@EventListener QuotesUpdated` loads, for the event's symbols, ACTIVE alerts from an in-memory index `symbol → alerts`. The index is rebuilt on alert changes (application events) and every 5 min.
- **Per alert:**
  1. Get the quote. Missing or **stale** → skip (fail-closed).
  2. `nowTrue = eval(...)`. `pct` = (price − reference)/reference × 100; `VOLUME_GTE` needs `matched_volume`, else skip.
  3. `wasTrue = GET alert:st:{id}`; then `SET` it to `nowTrue`.
  4. If `nowTrue && !wasTrue && status == ACTIVE`:
     - `INSERT alert_events (alert_id, session_date) ON CONFLICT DO NOTHING`;
     - if inserted, enqueue the notification and set the alert to `COOLDOWN` with `last_triggered_at`.
- **Session start:** the first `QuotesUpdated` of a trading day (or 09:00 VN) moves `COOLDOWN → ACTIVE`.
- **Expiry:** a job every 5 min moves alerts past `expires_at` to `EXPIRED`.
- **Account deletion:** on `AccountDeletionRequested`, set every alert of the user to DELETED and delete the user's devices.

### Notifications

**Content and API:**

- Alert notification text: title "Cảnh báo giá {SYMBOL}"; body for example "Giá {SYMBOL} đạt {price} (≥ {threshold}) lúc {hh:mm}". Neutral wording only (no "nên").
- `notification.api.NotificationService.notify(userId, kind, title, body, deepLink, channels)`:
  - always inserts the inbox row;
  - for each of EMAIL and PUSH: if P2 is not granted, mark the outbox row `SKIPPED`;
  - EMAIL alerts are limited to 5 per user per day (Redis), beyond that `SKIPPED`.
- **Inbox:** `GET /notifications?cursor=` and `POST /notifications/{id}/read`.
- **Devices:** `POST /devices {platform: EXPO|WEB_PUSH, token}` (upsert, `last_seen_at`) and `DELETE /devices/{id}`.

**Outbox dispatcher** (from WP-04, extended):

- Channels: `SmtpEmailChannel`, `ExpoPushChannel`, `WebPushChannel`, `LogEmailChannel`.
- Batch 50; `FOR UPDATE SKIP LOCKED`; backoff 10 s / 60 s / 5 min, then `FAILED`.

| Channel | Details |
|---|---|
| `SmtpEmailChannel` | Spring Mail. Active when `SMTP_HOST` is set; otherwise `LogEmailChannel`, the dev default |
| `ExpoPushChannel` | `POST https://exp.host/--/api/v2/push/send`, up to 100 messages per request. Handle the per-message `DeviceNotRegistered` by deleting the device. Optional `EXPO_ACCESS_TOKEN` |
| `WebPushChannel` | VAPID with a maintained free library (for example `nl.martijndwars:web-push` + BouncyCastle). A 404 or 410 from the push service deletes the device |
| PUSH fan-out | One message to all of the user's devices |

## Tests

### Alerts

- **Rule validation:** each condition's bounds; 21st alert → `LIMIT_EXCEEDED`; EMAIL without P2 → 400.
- **Evaluator:**
  - false → true fires exactly once;
  - true → true does not fire;
  - after a COOLDOWN reset at the next session it fires again;
  - stale quote → no fire;
  - expired alert → no fire;
  - unique `(alert_id, session_date)` under 2 concurrent events.
- **Latency:** `QuotesUpdated` → outbox row ≤ 1 s for 200 alerts.

### Notifications

- **Consent:** P2 revoked between creation and firing → inbox row present, EMAIL/PUSH `SKIPPED`.
- **Email cap:** 6th alert email of the day → `SKIPPED`.
- **Expo (WireMock):** success; `DeviceNotRegistered` deletes the device; a 5xx is retried with backoff and then `FAILED`.
- **Web Push:** the request has VAPID `Authorization` and an `aes128gcm` body (use the library's test utilities); 410 deletes the device.
- **SMTP:** a GreenMail test receives the email.
- **Account deletion:** alerts DELETED and devices removed.

### General

- `ModularityTests`; coverage ≥ 80% for `alerting` and `notification`.
