## Goal

Administrators log in with a password plus TOTP. They can:

- manage users (list, search, lock, unlock);
- create, list and revoke invite codes;
- publish new terms versions;
- toggle feature flags.

Every privileged action and every security-relevant event is written to the append-only `core.audit_log`.

## Design

### TOTP (RFC 6238)

- 30 s step, 6 digits, HMAC-SHA1, tolerance ±1 step.
- Implement it yourself (about 40 lines, `javax.crypto.Mac`) or use a maintained free library. Test vectors from **RFC 6238 Appendix B** must pass.
- The secret is stored in `core.users.totp_secret_enc`, encrypted with **AES-256-GCM**:
  - key from `APP_ENCRYPTION_KEY` (base64, 32 bytes; dev generates an ephemeral key and warns);
  - stored as random 12-byte IV ‖ ciphertext ‖ tag.
- **Replay protection:** a time step that was already accepted for this admin is rejected (Redis `totp:last:{userId}`, TTL 90 s).
- `identity.internal.TotpSecondFactor implements AdminSecondFactor` replaces the reject-all implementation from WP-04. A missing or wrong TOTP → 401 `UNAUTHENTICATED`, plus `security_events.TOTP_FAIL`.

### Admin bootstrap

The first admin is created **only** from the command line, never over HTTP:

- `java -jar core.jar --app.bootstrap-admin.email=<email>` with profile `admin-bootstrap`.
- It creates an `ACTIVE` ADMIN user with a random 20-character password and a TOTP secret.
- It prints **once** to stdout: the password and the `otpauth://totp/VN%20Stock%20AI%20Pro:<email>?secret=...&issuer=VN%20Stock%20AI%20Pro` URI. Then it exits.
- If the email already exists, it refuses.
- Document it in `services/core/README.md`.

### Authorization

- Every `/api/v1/admin/**` endpoint requires `role=ADMIN` from the JWT (`hasRole('ADMIN')`), otherwise 403 `FORBIDDEN`.

### Endpoints

| Endpoint | Behaviour |
|---|---|
| `GET /admin/users?query=&status=&cursor=&limit=` | Cursor pagination by `created_at, id`. Fields: id, email, displayName, status, role, createdAt, lastLoginAt (from `security_events`). **Never** returns hashes, tokens or secrets |
| `POST /admin/users/{id}/lock` / `unlock` | `ACTIVE ↔ SUSPENDED`. Locking revokes all refresh tokens. An admin cannot lock themselves. A reason is required (≤ 200 chars) and goes into the audit detail |
| `GET /admin/invites`, `POST /admin/invites`, `POST /admin/invites/{id}/revoke` | FR-217. The code format is `VSAP-XXXX-XXXX` (Crockford base32, from `SecureRandom`). Store SHA-256; return the code only in the create response. List: label, maxUses, usedCount, expiresAt, revokedAt (never the code) |
| `POST /admin/terms {kind, version, title, contentMd}` | Inserts an immutable version (the DB trigger already prevents updates). `version` must be unique; `kind` is TERMS, PRIVACY or DERIVATIVE_RISK. Publishing makes it current, which triggers the gate from WP-05 |
| `GET /admin/flags`, `PUT /admin/flags/{key} {enabled}` | Only existing keys (404 otherwise); sets `updated_by` |
| `shared.FeatureFlags.isEnabled(key)` | Read API for other modules, cached 30 s. `identity` uses it for `beta_invite_only` instead of reading the table directly; refactor this |

### Audit writer (`audit` module, FR-216)

- A synchronous `@EventListener` for every `shared.AuditableEvent` inserts into `core.audit_log` in the **same transaction**, with `correlationId` from MDC.
- Make the WP-04 and WP-05 events implement `AuditableEvent`, and add the missing ones: `LoginSucceeded`, `LoginFailed`, `AccountLocked`, `PasswordChanged`, `TokenReused`, `TermsAccepted`, `ConsentChanged`, `AccountDeletionRequested`, `AccountErased`, `UserSuspended`, `UserUnsuspended`, `InviteCreated`, `InviteRevoked`, `TermsPublished`, `FeatureFlagChanged`.
- `detail` must contain **no** email, password or token. Add a test that scans every event's detail keys.

## Tests

- **RFC 6238 test vectors**, SHA1 rows.
- **TOTP login:** correct code → tokens; wrong code → 401 and `TOTP_FAIL`; the same code reused within its window → 401 (replay); a code outside ±1 step → 401.
- **AES-GCM:** encrypt/decrypt round-trip; tampered ciphertext → exception.
- **Bootstrap runner:** creates the admin with an encrypted TOTP secret; refuses an existing email; prints the URI once.
- **Admin endpoints:**
  - a USER token gives 403 on every `/admin/**`;
  - the user list never contains `passwordHash`, token or secret fields (JSON assertion);
  - lock revokes tokens and blocks login (403 `FORBIDDEN`);
  - an admin cannot lock themselves;
  - unlock works.
- **Invites:** the code is returned once and only its hash is stored; revoking it blocks registration (`INVITE_INVALID`); the list never contains codes.
- **Terms publish:** a duplicate version → 409 `CONFLICT`; after publishing, a previously compliant user gets 403 `TERMS_NOT_ACCEPTED`.
- **Flags:** toggling `beta_invite_only` off allows registration without an invite (within the cache TTL); an unknown key → 404.
- **Audit:**
  - each action above inserts exactly one `audit_log` row with the right action and actor;
  - `UPDATE core.audit_log` fails (DB trigger);
  - details contain no PII.
- **`ModularityTests`** pass.
- **Coverage:** ≥ 80% for `admin`, `audit` and the TOTP code.
