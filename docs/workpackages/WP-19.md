## Goal

Every user has a virtual account. They can:

- place LO/MP orders on stocks;
- have orders validated by RiskGuard and filled by the published rules;
- see every cash and share movement as immutable ledger entries;
- see their positions, NAV and P&L.

Shares settle T+2. Unfilled LO orders expire after ATC. A user-set drawdown halts new buys. A nightly reconciliation proves that the ledger and the positions agree.

## Rules

### Account (FR-100, ST-04)

- **Lazy creation:** the first call to any `/paper/**` endpoint creates the account `ACTIVE` with `initial_cash` and `peak_nav = initial_cash`, plus one `INITIAL_DEPOSIT` CASH entry.
- **Reset (FR-114):** the old account becomes `ARCHIVED` (with `archived_at`), and a new `ACTIVE` account is created. History is kept.
- **Settings (FR-107, FR-108):** `maxOrderValue`, `maxDailyValue` (VND, > 0, or null) and `maxDrawdownPct` (0 < x ≤ 100, or null) can be updated.

### Placing an order (`POST /paper/orders`)

**Request:**

- The `Idempotency-Key` header (uuid) is required and maps to `client_order_id`.
- A repeated key returns the **original** result with the same status code, and does not create a new order.

**Concurrency:** lock the account row with `SELECT ... FOR UPDATE` for the whole placement, so concurrent orders cannot overspend.

**RiskGuard** runs these rules in order and stops at the first violation (ALG-10):

| # | Rule | Rejects when | Code |
|---|---|---|---|
| 1 | `SessionRule` | the quote is missing or older than `stale_after_seconds` | `DATA_STALE` (HTTP 503) |
| | | MP while the session ≠ `CONTINUOUS` | `RISK_SESSION` |
| | | LO while the session ∉ {`PRE_OPEN`, `ATO`, `CONTINUOUS`, `ATC`} | `RISK_SESSION` |
| 2 | `LotSizeRule` | `quantity % lot_size != 0` or `quantity ≤ 0` | `RISK_LOT_SIZE` |
| 3 | `PriceBandRule` (LO only) | limit outside `[floor, ceiling]` | `RISK_PRICE_BAND` |
| | | `limit % tick != 0` | `RISK_TICK_SIZE` |
| 4a | `CashRule` (BUY) | `available_cash < qty × px + fee(qty × px)`, where `px` = limit (LO) or the last price (MP) | `RISK_INSUFFICIENT_CASH` |
| 4b | `SharesRule` (SELL) | `available_shares < qty` | `RISK_INSUFFICIENT_SHARES` |
| 5 | `OrderLimitRule` | `qty × px > maxOrderValue` | `RISK_ORDER_LIMIT` |
| 6 | `DailyLimitRule` | today's accepted orders' value (status ≠ REJECTED) + `qty × px > maxDailyValue` | `RISK_DAILY_LIMIT` |
| 7 | `HaltRule` | account `HALTED` and side BUY | `RISK_HALTED` |

Definitions used by rule 4:

- `available_cash` = Σ CASH entries − Σ `reserved_cash` of OPEN orders.
- `available_shares` = Σ SECURITY entries with `available_on ≤ today` − Σ `reserved_qty` of OPEN sell orders.

**Rejection:** a rejected order is persisted as `REJECTED` with `reject_code`, and the response is the problem+json with that code (422, or 503 for `DATA_STALE`). It creates **no** ledger entries.

### Fills (FR-109, ALG-11)

| Case | Fill |
|---|---|
| MP | Fills immediately and completely at the last price |
| LO buy, `last_price ≤ limit` | Fills immediately at the **limit** price |
| LO sell, `last_price ≥ limit` | Fills immediately at the **limit** price |
| LO not marketable | Becomes `OPEN`, with `reserved_cash = qty × limit + fee(qty × limit)` (buy) or `reserved_qty = qty` (sell) |

**Matching OPEN orders:**

- Listen to `quotes::api.QuotesUpdated(symbols, cycleTs)`.
- For OPEN orders on those symbols, if the quote is fresh and the fill condition holds, fill each order in its **own** transaction, locking the account.
- A fill clears the reservation.

**Cancel (FR-113):** `DELETE /paper/orders/{id}` on an OPEN order of the caller → `CANCELLED` and the reservation is released. Anything else → 409 `CONFLICT` or 404.

**Expiry:** at `expiry_time` on trading days, every OPEN order with `session_date ≤ today` → `EXPIRED`, and the reservation is released.

### Ledger posting (ALG-12)

Everything is in the fill's transaction, `long` VND throughout:

- `gross = qty × price`. Since price has 2 decimals, compute with `BigDecimal` and require a whole number of VND; a fraction is impossible because tick sizes are whole VND.
- `fee = roundHalfUp(gross × fee_rate)`.
- `tax = roundHalfUp(gross × sell_tax_rate)` (SELL only).

| Side | Entries |
|---|---|
| BUY | `BUY_COST` CASH −gross; `FEE` CASH −fee; `BUY_SHARES` SECURITY +qty, `available_on = addTradingDays(trade_date, 2)` |
| SELL | `SELL_SHARES` SECURITY −qty (`available_on = trade_date`); `SELL_PROCEEDS` CASH +gross; `FEE` CASH −fee; `TAX` CASH −tax |

- **Trading-day arithmetic** (`addTradingDays`): `market.trading_calendar`, falling back to weekdays when a date is missing. Log when the fallback is used.
- **Positions** (upsert in the same transaction):
  - BUY: `avg_cost = (avg_cost × q_old + gross + fee) / (q_old + qty)`, 4 decimals HALF_UP.
  - SELL: `realized_pnl += gross − fee − tax − round(avg_cost × qty)`; `avg_cost` is unchanged; a quantity of 0 keeps the row with `avg_cost = 0`.
- **Append-only:** never update or delete `ledger_entries`; the DB trigger enforces this.

### NAV, peak and halt (ALG-13)

- `NAV = cash + Σ position_qty × last_price`. If a price is stale, use the last close from `market.daily_bars` and flag `navPriceBasis = CLOSE` in the response.
- On `QuotesUpdated`, recompute NAV for accounts holding those symbols:
  - update `peak_nav = max(peak_nav, NAV)`;
  - if `maxDrawdownPct` is set and `(peak − NAV) / peak × 100 ≥ maxDrawdownPct` → `HALTED` with `halted_at`.
- `POST /paper/account/resume` → `ACTIVE`, and `peak_nav` is reset to the current NAV.

### Reconciliation (NFR-A04)

- A nightly job at 01:30 checks every non-archived account:
  - `positions.quantity_total == Σ SECURITY entries` per symbol;
  - cash (Σ CASH) ≥ 0.
- Insert a `paper.reconciliation_runs` row.
- Any mismatch → that account `HALTED`, details recorded, ERROR log with `alert=true`.

## Tests (Testcontainers Postgres + Redis; fixed `Clock`; seeded `market.symbols` and `market.trading_calendar`)

### RiskGuard

One positive and one negative test per rule, including:

- stale quote → 503 `DATA_STALE`;
- MP during `ATO` → `RISK_SESSION`;
- LO at the exact floor and at the exact ceiling → accepted;
- one tick above the ceiling → `RISK_PRICE_BAND`;
- HOSE price 49,950 vs 50,000 tick boundaries.

### Golden numbers

Write the expected values in the test, computed by hand. Initial cash 500,000,000; fee 0.15%; tax 0.1%.

1. **BUY MP 1,000 FPT @ 57,400:**
   - gross 57,400,000; fee 86,100;
   - cash **442,513,900**;
   - avg cost **57,486.1000**;
   - shares available on T+2.
2. **SELL on T+1 → `RISK_INSUFFICIENT_SHARES`.**
3. **On T+2, SELL 1,000 @ 60,000:**
   - gross 60,000,000; fee 90,000; tax 60,000;
   - cash **502,363,900**;
   - realized P&L = 60,000,000 − 90,000 − 60,000 − 57,486,100 = **2,363,900**.

### Settlement calendar

- A buy on Friday becomes available on Tuesday.
- A holiday in `trading_calendar` adds one more day.

### Order lifecycle

- **LO resting:**
  - buy LO below the market → OPEN, with reserved cash checked;
  - a quote update with `price ≤ limit` → FILLED at the limit;
  - a cancel releases the reservation;
  - expiry at 14:50 → EXPIRED.
- **Idempotency:** the same key twice → one order, identical responses.
- **Concurrency:** 10 parallel BUYs that each fit alone but not all together → only the affordable number succeed; the others get `RISK_INSUFFICIENT_CASH`; cash never goes negative.

### NAV, halt, reset

- **Halt:** `maxDrawdownPct = 10`; the price drops so that NAV falls 10% from the peak → `HALTED`; BUY → `RISK_HALTED`; SELL is still OK; resume → ACTIVE.
- **Reset:** archived account kept; new account with initial cash; old orders still listed with `?accountId` if supported, otherwise documented.

### Integrity and access

- **Reconciliation:** tamper with a position quantity using raw SQL → the job flags the account and halts it.
- **Ledger immutability:** an `UPDATE` attempt fails.
- **Authorization:** another user's order id → 404; no access to anyone else's account.
- **Coverage:** `paper` ≥ 85%.
