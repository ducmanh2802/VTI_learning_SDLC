## Goal

1. Anonymous product telemetry, recorded only with consent P3.
2. Feedback and complaint tickets.
3. Public content pages: indicator explanations, plan limits, simulation rules, incident status.
4. A monthly metrics report for the admin.

## In scope

- `services/core/src/main/java/vn/stockai/core/{telemetry,support}/**`, `.../admin/**` (metrics)
- `db/migrations/V3__content_pages_seed.sql`
- Tests
- `docs/workpackages/reports/WP-23.md`

## Design

### Telemetry (FR-223, FR-224)

**`POST /events {events: [...]}`:**

- Authenticated. Max 50 events; each `properties` ≤ 2 KB JSON.
- `event` must be in the PRD 6.2 allow-list; otherwise drop that event and count it in the response `{accepted, dropped}`. HTTP 202.
- If `ConsentQuery.isGranted(user, "P3")` is false → accept the request but store nothing (`accepted = 0`).
- Store `core.product_events` with `user_ref` from `UserRefs.of(userId)`, `platform` and `occurred_at` (clamped to now ± 24 h).
- **Property allow-list per event** (from PRD 6.2). Unknown keys are dropped. **Reject any value that looks like an email or a phone number**: reuse the PII regexes in a small Java util with tests.

**Server-side events:** `telemetry` listens to `AuditableEvent` and maps:

| Audit event | Product event |
|---|---|
| user registered | `signup_completed` |
| email verified | `email_verified` |
| terms accepted | `terms_accepted` |
| consent changed | `consent_changed` |
| account deletion requested | `account_deletion_requested` |

The same P3 rule applies, with `platform = server`.

**Retention:** a nightly job deletes rows older than 13 months (DR-010).

### Support (FR-220, FR-221)

- **`POST /feedback {category, message}`:**
  - Creates a ticket with code `FB-{yyyy}-{6-digit sequence}`.
  - Enqueues an in-app notification to the user ("Đã nhận phản hồi {code}").
  - Logs an ERROR-free INFO entry for the admin.
  - Max 5 per user per day.
- **`GET /content/status`** (public): the active `status_messages` (`starts_at ≤ now < ends_at`, or `ends_at` null).
- Admins create and end status messages through `POST /admin/status`. If the contract has no such endpoint, use the existing admin pattern and **report the contract gap**; do not invent a public path.

### Content (FR-054, FR-109, FR-180)

- `V3__content_pages_seed.sql` inserts these Vietnamese, neutral pages:
  - `indicator.sma`, `indicator.ema`, `indicator.rsi`, `indicator.macd`, `indicator.bollinger`, `indicator.atr`, `indicator.volume_ma`: 3–5 sentences each, explaining what the indicator measures, with no trading advice;
  - `limits.free`: 10 AI questions per day, 5 watchlists × 50 symbols, 20 active alerts;
  - `paper.fill-rules`: the WP-19 rules in plain words: MP fill, LO fill at limit, no partial fills, expiry after ATC, T+2, fee 0.15%, sell tax 0.1%, starting cash 500,000,000 VND, "không phản ánh kết quả thực".
- `GET /content/indicators`, `GET /content/limits` and `GET /content/fill-rules` read these pages (public, cache 10 min).

### Monthly metrics (FR-215)

**`GET /admin/metrics?month=yyyy-MM`** returns:

| Metric | Computation |
|---|---|
| MET-001 MAU | Distinct users with `LOGIN_OK` in the last 30 days of that month, from `core.security_events`. If retention removed the data, use `product_events.session_started` and say which source |
| MET-011 M3 retention | For the cohort that registered in month−3, the share active in the target month |
| MET-010 | Share of VIOLATION among reviewed samples in the month, via the Analytics review stats (add a query param, or count from the review list) |
| MET-008, MET-012 | `null`, with `"source": "manual"` (entered by the founder outside the system in R1) |

Each metric carries its definition text (BRD 4.2) and its data source.

## Tests

- **Telemetry:** P3 off → nothing stored; P3 on → stored with `userRef`, not `userId`; unknown event dropped; 51 events → 400; an email in a property → that property dropped; server events mapped; retention job.
- **Feedback:** code format and sequence; 6th in a day → 429.
- **Status:** active window logic.
- **Content:** seeded pages exist; the texts contain no forbidden advice words (reuse the WP-11 list in a Java test).
- **Metrics:** MAU, retention and MET-010 computed on seeded data; manual metrics are `null`.
- **Coverage:** ≥ 80%.
