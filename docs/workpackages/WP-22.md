## Goal

Everything needed to run R1 on **one free VM** is in the repo and tested locally:

- the production compose override;
- the Caddy config (TLS, static web, `/api` proxy, security headers);
- encrypted backups to S3-compatible storage, and a restore drill;
- a bootstrap script;
- a GitHub Actions deploy workflow;
- runbooks.

Creating the cloud accounts (Oracle, DuckDNS, object storage) is a **founder action**. This WP produces the scripts and the instructions; it does not create accounts.

## Design

### `docker-compose.prod.yml` (override)

- No host ports except Caddy 80/443.
- The `internal` network is `internal: true` for postgres, redis, core and analytics. Caddy joins `edge` and `internal`.
- Images come from GHCR, tag `${IMAGE_TAG}`.
- Limits as in SDD 3.10.2; `restart: unless-stopped`; json-file log rotation (`max-size: 20m`, `max-file: 5`).

### Caddy

- Site `${PUBLIC_HOST}` (for example `name.duckdns.org`), automatic HTTPS (Let's Encrypt).
- Serves the web `dist` as static files with an SPA fallback to `index.html`.
- `/api/*` → `core:8080`.
- `/internal/*` is **never** routed (explicit 404).
- Health: `/api/v1/health` is passed through.
- **Headers:**
  - `Strict-Transport-Security` (1 year);
  - `Content-Security-Policy`: `default-src 'self'; img-src 'self' data:; connect-src 'self'; script-src 'self'; style-src 'self'; font-src 'self'; frame-ancestors 'none'; base-uri 'self'`;
  - `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` (minimal).
- zstd/gzip compression. Basic rate limit on `/api/v1/auth/*` if the free Caddy build supports it; otherwise document that Core enforces it.

### Backups (SDD 3.5.5)

**`backup.sh`:**

- `pg_dump -Fc` (through the postgres container) | `age -r $BACKUP_AGE_RECIPIENT` | upload to S3-compatible storage with the AWS CLI or `rclone`, both free.
- Variables: `BACKUP_S3_ENDPOINT`, `BACKUP_S3_BUCKET`, `BACKUP_S3_KEY`, `BACKUP_S3_SECRET`.
- Retention: 7 daily + 4 weekly (prune by name date).
- Exit code ≠ 0 on any failure. Secrets are never echoed.

**`restore.sh <object>`:** download → `age -d -i $BACKUP_AGE_IDENTITY_FILE` → `pg_restore --clean --if-exists` into a target database.

**Local restore drill:** a script `infra/scripts/drill.sh` that:

1. starts a local MinIO;
2. runs backup → restore into a fresh postgres;
3. compares row counts of every table.

It must pass on the dev machine with Docker.

### `bootstrap.sh` (Ubuntu 24.04 LTS on ARM64 or AMD64)

- Installs Docker and the compose plugin.
- Creates the `deploy` user and `/opt/vnstockai`.
- Copies the compose files, the Caddyfile and `.env` (from a local file **never** committed).
- Enables `unattended-upgrades` and the UFW firewall (22, 80, 443).
- Installs a cron job: backup daily at 01:00.

### CI and CD

**`images.yml`:** on push to `main` and `integration/**`, build **multi-arch** (`linux/amd64,linux/arm64`) images for core, analytics and web. The web image is a Caddy image with the built `dist`. Push them to GHCR with `docker/build-push-action` and QEMU.

**`deploy.yml`:**

- `workflow_dispatch` with an image tag.
- SSH to the VM using the secrets `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`.
- Run `deploy.sh`: pull, run the migrator, `up -d`, health check, automatic rollback to the previous tag if the health check fails within 60 s (QAS-12).

## Tests and checks

- `docker compose -f infra/docker-compose.yml -f infra/docker-compose.prod.yml --env-file infra/.env.prod.example config --quiet` → exit 0. Add `infra/.env.prod.example` with placeholders.
- `caddy validate` (run in the Caddy container) on the Caddyfile → valid.
- **Local prod-like smoke:**
  - run with `PUBLIC_HOST=localhost` and Caddy's internal TLS;
  - `curl -k https://localhost/api/v1/health` → 200;
  - `curl -k https://localhost/internal/v1/health/live` → 404;
  - the response headers include the CSP and HSTS.
- `drill.sh` passes.
- `shellcheck` (Docker image) on every script → no errors.
- The workflows lint with `actionlint` (Docker image).
