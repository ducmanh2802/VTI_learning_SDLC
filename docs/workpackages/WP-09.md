## Goal

When a market-data source fails repeatedly, the provider layer switches to the next source for that kind of data. Provenance records the source that actually served the value.

> **Note.** SDD 7.7 planned direct KBS/VPS adapters. These are **replaced** by vnstock's own `source` parameter: direct endpoints carry an unresolved terms-of-use question (SRS OQ-051).

Facts measured on 2026-10-21 with vnstock 5.1.0, Guest tier:

| Call | Accepted sources | Notes |
|---|---|---|
| `equity(...).quote(source=...)` / `price_board` | `kbs`, `vci`, `asean` | `kbs` and `vci` both return identical data on the Guest tier |
| `equity(...).ohlcv(source=...)` | `vci`, `asean`, `mas`, `kbs`, `vnd` | — |

## Design

### `FailoverProvider` (implements `MarketDataProvider`)

- It wraps an ordered list of `(label, provider)`. Build it from config:
  - `PROVIDER_CHAIN_QUOTES=vnstock:kbs,vnstock:vci`
  - `PROVIDER_CHAIN_BARS=vnstock:kbs,vnstock:vci,vnstock:vnd`
- `VnstockProvider` takes a `source` argument that is passed to every vnstock call that supports it. Each element of the chain gets its own `VnstockProvider(source=...)` instance. **All instances share one rate limiter**, because they are the same library and the same machine.
- **Failure counting:** a `ProviderError` or `RateLimited` counts as a failure for that `(capability, label)`.
  - After **3 consecutive failures**, the label is skipped for that capability for 10 minutes.
  - After that, one trial call is made (half-open).
- **Capability unavailable:** a `CapabilityUnavailable` is **not** a failure. It is re-raised only when **every** element reports it.
- **When everything fails:** raise `ProviderError("all sources failed", tried=[...])`.
- **Provenance:** `Provenance.provider` becomes `vnstock:kbs`, `vnstock:vci`, and so on.
- **Health snapshot:** `health_snapshot()` returns, per `(capability, label)`: `{consecutive_failures, open_until, last_success_at, last_error}`. WP-10 and WP-13 expose it on `/ops/ingestion`.

## Tests

- First source OK → used, provenance shows it.
- First source raises 3 times → the 4th call goes straight to the second source; after 10 min (fake clock), one trial call hits the first source again.
- `CapabilityUnavailable` from one source → the next source is tried. From all sources → `CapabilityUnavailable` is raised.
- All sources failing → `ProviderError` that lists every source tried.
- The shared rate limiter is used: two sources do not double the request rate.
- The health snapshot shows the right counters.
- Live test (`@pytest.mark.live`): a chain `kbs,vci` returns the FPT quote.
- Coverage: `analytics.providers` stays ≥ 80%.
