## Goal

Users manage up to **5** watchlists of up to **50** symbols each. Both limits come from config (`app.limits.watchlists=5`, `app.limits.watchlist-items=50`). The list view shows each symbol's latest quote, with staleness.

## Endpoints (per `dist/public.yaml`)

| Endpoint | Behaviour |
|---|---|
| `GET /watchlists` | The caller's lists ordered by `sortOrder`, with items. Each item has `{symbol, sortOrder, quote}`. `quote` comes from `quotes::api.QuoteReader.latest(symbols)` in **one** batch call: `{price, change, pct, stale, asOf}`, or `null` if missing. Missing or stale data is shown as such (fail-closed) |
| `POST /watchlists {name}` | Name 1–50 chars, unique per user (409 `CONFLICT`). More than 5 lists → 409 `LIMIT_EXCEEDED` |
| `PATCH /watchlists/{id}` | Rename and/or `sortOrder` |
| `DELETE /watchlists/{id}` | Delete the list |
| `PUT /watchlists/{id}/items/{symbol}` | Idempotent. Unknown symbol → 404. More than 50 items → 409 `LIMIT_EXCEEDED`. A `sortOrder` body is optional |
| `DELETE /watchlists/{id}/items/{symbol}` | Remove the item |

- Another user's list → 404, never 403.
- Personal data: the contributor exports the lists; the eraser deletes them.
